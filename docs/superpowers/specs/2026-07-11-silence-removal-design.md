# 무음 구간 제거 프로그램 설계

**날짜**: 2026-07-11
**상태**: 설계 승인 대기

## 목적

녹화·녹음 파일에서 조용한(무음) 구간을 자동으로 짧게 줄여 정리하는 CLI 도구.
영상과 오디오를 모두 지원하고, 파일 하나 또는 폴더 일괄로 처리한다.
대용량 파일이 많은 상황을 전제로 **속도 최적화**와 **품질(화질/음질/싱크) 보존**을 1급 제약으로 둔다.

## 범위

**포함**
- 영상(mp4 등) / 오디오(mp3, wav 등) 무음 축소
- 파일 단일 또는 폴더 일괄 처리
- 무음을 완전 삭제가 아니라 짧게 남기는 방식 (자연스러운 호흡 유지)
- 에이전트/LLM이 호출·파싱할 수 있는 구조화 출력(`--json`)

**제외 (별도 프로젝트로 예약)**
- 내용 기반 편집(전사 + LLM으로 군더더기/NG 테이크/잡담 제거). 무음 기반이 아니라 내용 기반이라 별개 제품. 본 도구의 출력을 입력으로 받는 2단계 파이프라인으로 확장 가능.
- GUI, 드래그앤드롭
- MCP 서버 래핑 (본 설계의 `--json` 규약 위에 나중에 얇게 얹을 수 있게 여지만 열어둠)

## 핵심 결정 사항

| 항목 | 결정 |
|------|------|
| 실행 방식 | CLI |
| 대상 | 영상 + 오디오 |
| 입력 단위 | 파일 / 폴더 둘 다 (폴더면 일괄) |
| 무음 처리 | 짧게 줄이기 (완전 삭제 아님) |

| 빠른 모드 | `--copy` (스트림 복사, 키프레임 스냅, 무손실·초고속, 미세 싱크오차 감수) |

## 아키텍처

Python이 오케스트레이션하고 무거운 미디어 작업은 ffmpeg가 전담한다. 역할별 모듈 분리:

| 모듈 | 역할 | 의존 |
|------|------|------|
| `cli.py` | 인자 파싱, help, 파일/폴더 판별, 진행상황·JSON 출력, 종료 코드 | detector, segments, processor |
| `detector.py` | ffmpeg `silencedetect`로 무음 구간 목록 추출 | ffmpeg |
| `segments.py` | 무음 목록 → keep 구간 계산. **순수 함수, ffmpeg 무관** | 없음 |
| `processor.py` | keep 구간대로 잘라 이어붙이기 (영상/오디오 분기) | ffmpeg |
| `ffmpeg_utils.py` | ffmpeg 존재 확인, 하드웨어 인코더 감지, 명령 실행 | ffmpeg |

**핵심 설계 원칙**: 시간 구간 계산(`segments.py`)을 ffmpeg에서 완전히 분리한다.
이 계산이 프로그램의 두뇌이며, 순수 함수로 두면 실제 미디어 파일 없이 단위 테스트가 가능하다.

## 핵심 알고리즘

### ① 무음 감지 (detector)

```
ffmpeg -i input -af silencedetect=noise=<threshold>dB:d=<min-silence> -vn -f null -
```

- `-vn`으로 **오디오만 디코딩** → 영상 디코딩 비용 0 (대용량 최적화의 핵심)
- stderr의 `silence_start` / `silence_end` 시각을 파싱해 무음 구간 목록 생성

### ② keep 구간 계산 (segments — 순수 함수)

입력: 무음 구간 목록, 전체 길이, `min-silence`, `keep-silence`
출력: 최종 keep 타임라인 (시작~끝 시각 목록)

로직:
1. 무음 목록을 반전해 말하는 구간을 구함
2. 각 무음(길이 ≥ `min-silence`)을 완전 삭제하지 않고 **`keep-silence`초만 남김**
3. 남기는 무음은 **앞뒤 절반씩 배분** (예: 0.3s → 앞 말 구간 뒤 0.15s + 뒤 말 구간 앞 0.15s)
   - 이렇게 하면 "자연스러운 호흡"과 "말 끝 여린 소리(자음 꼬리) 보호"를 한 값으로 동시에 해결
4. 인접·겹치는 구간을 병합해 최종 keep 타임라인 산출

> 설계 노트: 초기 안에는 `padding`과 `keep-silence`가 따로 있었으나, 말 구간 양쪽 padding의 합이 곧 남는 무음 길이가 되어 두 파라미터가 중복·충돌했다. `keep-silence` 하나로 통합했다.

### ③ 잘라 이어붙이기 (processor)

- **오디오**: keep 구간 추출 후 concat. 오디오 재인코딩은 가볍고 프레임 단위로 정밀하므로 원본 동급 고품질(또는 무손실)로 재인코딩.
- **영상**: 모드에 따라 분기 (아래 품질·최적화 참조), A/V 싱크 유지.

## 품질 & 최적화 전략

### 품질 보존

- **오디오**: 무손실 또는 원본 동급 고비트레이트 재인코딩. 프레임 단위 정밀 컷.
- **영상**: 두 모드 제공.

| 모드 | 방식 | 화질 | 속도 | 컷 정밀도 | A/V 싱크 |
|------|------|------|------|-----------|----------|
| `precise` (기본) | 단일 패스 재인코딩(`filter_complex`), CRF 18 | 시각적 무손실 | 느림(HW 가속으로 완화) | 프레임 단위 | **항상 100% 보장** |
| `copy` (`--copy`) | 스트림 복사, 키프레임 스냅, 자기완결 조각 concat | 무손실 | 매우 빠름 | 키프레임 단위 | 미세 오차 누적 가능 |

**모드 선택 근거**: `copy`는 영상이 키프레임에서만 잘리고 오디오는 더 촘촘히 잘려, 조각마다 영상/오디오 길이가 몇 ms씩 어긋난다. 무음 제거는 컷이 수십~수백 개 생겨 이 오차가 누적되면 싱크가 밀릴 수 있다. 키프레임 스냅으로 완화하지만 0은 아니다. `precise`는 오디오·타임스탬프를 전부 다시 흘려 싱크를 항상 보장한다. 대용량·다수 파일 + 싱크 필수 요구를 함께 만족시키기 위해 **`precise`를 기본**으로 하고, 하드웨어 가속으로 속도를 확보한다.

### 최적화 (대용량·다수 파일)

1. **무음 감지 시 오디오만 디코딩**(`-vn`) — 영상 디코딩 비용 제거. 가장 큰 절약.
2. **하드웨어 인코더 자동 감지** (NVENC/QSV/AMF) → `precise` 재인코딩 속도 수 배 향상. 없으면 libx264 폴백.
3. **중간 임시파일 최소화** — 가능한 단일 패스 / concat demuxer로 불필요한 재인코딩·디스크 I/O 절감.
4. **폴더 일괄은 파일 단위 순차 처리** — ffmpeg가 이미 멀티코어를 다 쓰므로 파일 동시 실행은 디스크만 혹사시켜 오히려 느림. 순차가 정답.

## CLI 인터페이스

```
무음제거 <입력> [옵션]

입력:
  파일 또는 폴더 경로 (폴더면 안의 미디어 파일 일괄 처리)

옵션:
  -h, --help             사용법·옵션·예시 출력
  -o, --output DIR       출력 위치 (기본: 원본 옆 *_trimmed.확장자)
  --threshold DB         무음 기준 (기본: -30dB, 낮을수록 더 조용해야 무음 판정)
  --min-silence SEC      이 길이 이상만 무음으로 처리 (기본: 0.5s)
  --keep-silence SEC     잘라낸 무음에 남길 총 길이, 앞뒤 절반씩 (기본: 0.3s)
  --copy                 빠른 무손실 모드 (키프레임 스냅, 싱크 미세오차 감수)
  --dry-run              실제 처리 없이 잘릴 구간/예상 절감시간만 출력
  --json                 결과를 stdout에 JSON으로 출력 (에이전트용)
  -y, --yes              덮어쓰기 확인 생략
```

- **인자 없이 실행** → 에러 대신 help 출력, 종료 코드 `2`
- help 예시:
  ```
  무음제거 recording.mp4              # 파일 하나
  무음제거 ./녹화폴더                  # 폴더 일괄
  무음제거 talk.mp4 --keep-silence 0.5 --copy
  무음제거 ./영상들 --dry-run --json  # 예상 결과만 확인
  ```

## 에이전트 친화 (LLM이 호출·파싱 가능)

**`--json` 구조화 출력** (stdout 전용):

```json
{
  "results": [
    {
      "input": "recording1.mp4",
      "output": "recording1_trimmed.mp4",
      "status": "ok",
      "original_sec": 3600.0,
      "output_sec": 2712.5,
      "saved_sec": 887.5,
      "segments_kept": 143,
      "mode": "precise"
    },
    { "input": "broken.mp4", "status": "skipped", "reason": "no audio track" }
  ],
  "summary": { "total": 2, "ok": 1, "skipped": 1, "failed": 0 }
}
```

**규약**
- **종료 코드**: `0` 전체 성공, `1` 일부 실패, `2` 사용법/입력 오류
- **stdout/stderr 분리**: JSON은 stdout 전용, 진행·경고 로그는 stderr → 파싱 안전
- **`--dry-run --json`**: 처리 없이 예상 결과(절감 시간·컷 개수)를 같은 JSON 형식으로 → "확인 후 실행" 가능

## 에러 처리

- 시작 시 ffmpeg 존재 확인 → 없으면 Windows 설치 안내 출력, 종료 코드 `2`
- 지원 안 하는 파일 / 오디오 트랙 없는 영상 → 건너뛰고 경고, 일괄처리는 계속
- 폴더 일괄 중 한 파일 실패해도 나머지 계속, 마지막에 성공/실패 요약
- 무음이 하나도 없으면 원본 그대로 복사하고 알림
- 출력 파일 이미 존재 시 확인(`-y`로 생략)

## 테스트 전략

- **단위 테스트 (`segments.py`)**: 순수 함수라 ffmpeg 없이 테스트. 무음 목록 입력 → 기대 keep 구간 출력 검증. 경계값·겹침·연속 무음·무음 없음·전체 무음 등 케이스.
- **통합 테스트**: ffmpeg로 만든 짧은 합성 샘플(무음+톤 반복)로 실제 처리. 출력 길이·A/V 싱크·JSON 형식 검증.

## 향후 확장 여지

- **MCP 서버 래핑**: `--json` 규약 위에 얇게 얹어 대화 중 직접 호출
- **내용 기반 편집(별도 프로젝트)**: 전사(Whisper) + LLM으로 군더더기/NG/잡담 제거. 본 도구 출력을 입력으로 받는 2단계 파이프라인.
